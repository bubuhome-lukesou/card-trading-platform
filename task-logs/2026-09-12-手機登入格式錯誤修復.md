# 手機登入格式錯誤修復 — 2026-09-12

## 問題
淘寶式智能帳號框上線後，手機登入報「手機號碼格式不正確」

## 根源（前端）
`phone` computed getter 用 `replace(/^\+?\d{1,4}\s*/, '')` 剝區號：
- 正則 `\+?` 令「+」可選 → 用戶輸入**純數字** `66161315` 時，前綴 `6616` 被當成區號剝掉
- 剩低 `1315`（4 位）→ 後端 validatePhone 要求 ≥7 位 → 400 格式錯誤
- 用戶明明輸入咗完整號碼，被界面偷偷削短

## 修復（commit 9100ed52）
getter 改為**只在明確輸入「+」開頭嘅區號時先剝離**：
```js
const m = account.value.match(/^\+\d{1,4}(.*)$/)
return m ? m[1] : account.value
```
- `66161315` → 原樣直出（區號由左邊選單控制）✓
- `+85366161315` → 自動剝成 `66161315`（用戶手動打埋區號都接受）✓

## 驗證
- build ✓ → push → 伺服器 pull + build ✓
- 線上 LoginView chunk 確認新邏輯（match）存在、舊邏輯（replace）已移除 ✓
- 後端 send-code API 實測：`66161315` → 201 成功發送 ✓

## 教訓
「自動剝離」邏輯對純數字輸入係陷阱 — 澳門 8 位號碼前 1-4 位冚都係數字，任何前綴剝離都會切爛號碼。區號應該由 select 控制，帳號框只收純手機號（或明確 + 開頭嘅完整格式）。
