## 2. 拍賣 status filter 異常 — 真問題，已修（commit ae8c863c）

**根源：** `findAll()` 分頁發生在 effective-status 映射**之前**：
- DB 層撈 top-N（按 endTime DESC，包含大量 ended）
- 撈完先算 effectiveStatus，然後先過濾 status
- 小 limit（如 3、5、8）時 ended 拍賣擠爆分頁窗口 → active 被擠出 → `status=active` 返回 0
- 實測：limit=3/5/8/10/12 全部 0 筆、limit=15 得 1 筆、limit=20 先有 2 筆

**修復：** status 過濾下推 DB 層（分頁前）：
- `status=active`：`(endTime > now OR startTime > now) AND status != cancelled`（時間條件涵蓋 PENDING→ACTIVE 提前生效）
- `status=ended`：`(status = ended OR endTime <= now)`
- `status=pending`：`status = pending AND startTime > now`
- 應用層 effectiveStatus 精濾保留（雙保險）
- **賣家視圖（sellerId）不受影響**（原本就返回全部狀態）

**修復後驗證：**
- `?limit=3&status=active` → **2 筆**（原本 0）✓
- `?limit=3&status=ended` → 3 筆 ✓
- 無 filter limit=10 → total 正常 ✓
