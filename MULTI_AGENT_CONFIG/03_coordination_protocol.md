## 通信协议

### 1. 消息类型

| 类型 | 说明 | 优先级 |
|------|------|--------|
| `TASK_ASSIGN` | 任务分配 | 高 |
| `STATUS_REPORT` | 状态汇报 | 中 |
| `HELP_REQUEST` | 求助请求 | 高 |
| `TASK_COMPLETE` | 任务完成 | 中 |
| `ISSUE_ALERT` | 问题警报 | 高 |
| `COORDINATION` | 协调请求 | 中 |

### 2. 通信渠道

```
总管 ↔ Agent: sessions_send
Agent ↔ 总管：sessions_send (汇报)
Agent ↔ Agent: 通过总管中转
用户 ↔ 总管：直接对话
```

### 3. 响应时间要求

| 消息类型 | 响应时间 |
|---------|---------|
| TASK_ASSIGN | 5 分钟内 |
| HELP_REQUEST | 10 分钟内 |
| ISSUE_ALERT | 立即 |
| STATUS_REPORT | 按约定时间 |
| TASK_COMPLETE | 即时 |

{如何交接工作成果}

【交接方式】
1. 我提供数据格式文档
2. 你提供图表组件
3. 我集成到页面
```

## 冲突解决

### 1. 资源冲突

**场景**: 多个任务同时需要同一个 Agent

**解决流程**:
```
1. Agent 上报总管
2. 总管评估优先级
3. 调整任务顺序
4. 通知相关方
5. 更新计划
```

### 2. 意见分歧

**场景**: Agent 间对方案有不同意见

**解决流程**:
```
1. 各自说明理由
2. 总管评估方案
3. 选择最优方案
4. 执行决定
5. 记录经验
```

### 3. 任务延期

**场景**: 任务无法按时完成

**解决流程**:
```
1. 提前预警 (80% 时间时)
2. 说明原因
3. 评估影响
4. 调整计划
5. 通知用户
```

```
用户："开发一个投资分析页面，能查看股票数据和 Pokemon 卡牌价格"
```

#### 2. 总管分析并分配
```
总管 → Data Agent:
【任务】准备股票和卡牌数据
【优先级】高
【截止】今天 14:00
【需求】
- 股票 API 数据格式
- 卡牌价格数据
- 更新频率建议

总管 → Code Agent:
【任务】开发分析页面
【优先级】高
【截止】今天 18:00
【需求】
- 数据展示页面
- 图表可视化
- 实时更新

总管 → Media Agent:
【任务】设计页面 UI
【优先级】中
【截止】今天 12:00
【需求】
- 页面布局设计
- 配色方案
- 图标设计
```

#### 3. Agent 执行并汇报
```
Data Agent → 总管:
【状态】已完成
【交付】
- 股票数据 API 文档

- 示例数据文件

Code Agent → 总管:
