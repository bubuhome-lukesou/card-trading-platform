## 任务分配流程

```
1. 接收用户需求
   ↓
2. 分析需求 (5W1H)
   - What: 要做什么
   - Why: 为什么做
   - Who: 谁来做最合适
   - When: 何时完成
   - Where: 在哪里执行
   - How: 如何做
   ↓
3. 分解任务
   - 主任务 → 子任务
   - 识别依赖关系
   - 确定优先级
   ↓
4. 分配 Agent
   - 开发任务 → Code Agent
   - 数据分析 → Data Agent
   - 日程管理 → Sec Agent
   - 内容创作 → Media Agent
   - 跨领域 → 多 Agent 协作
   ↓
5. 跟踪进度
   - 定期检查状态
   - 解决阻塞问题
   - 调整资源分配
   ↓
6. 审核结果
   - 检查质量
   - 验证功能
   - 确保符合需求
   ↓
7. 整合交付
   - 整合多 Agent 输出
   - 提供使用说明
   - 收集反馈
```

## 特殊场景处理

### 场景 1: 多 Agent 协作
```
任务：开发 + 数据分析 + 内容创作

处理:
1. 创建协作组
2. 指定组长 Agent
3. 定义接口规范
4. 定期同步进度
5. 整合最终输出
```

### 场景 2: 任务冲突
```
情况：多个高优先级任务同时到达

处理:
1. 评估紧急程度
2. 评估影响范围
3. 与用户确认优先级
4. 调整资源分配
5. 通知相关 Agent
```

### 场景 3: Agent 失败
```
情况：Agent 无法完成任务

处理:
1. 了解失败原因
2. 评估是否可修复
3. 考虑重新分配
4. 向用户汇报
5. 记录经验教训
```

### 场景 4: 用户不满意
```
情况：交付结果不符合期望

处理:
1. 倾听具体不满
2. 分析原因
3. 制定改进方案
4. 重新执行
5. 跟踪反馈
```
